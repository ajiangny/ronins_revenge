# CLAUDE.md

Shadow Blade: Ronin vs. Samurai — a Space Invaders remake for CSCI 381/780 Assignment 1 (individual work).
Unity 6000.6.6f1, URP, new Input System. Single scene: `Assets/Scenes/SampleScene.unity`.

**Read [ARCHITECTURE.md](ARCHITECTURE.md) first** to find a system: game flow, player combat, boons,
samurai army, scouts, bosses, UI, VFX/audio, and the `Ninja/…` editor commands. Keep it up to date when you
add or move a system, enemy or boss. [README.md](README.md) is the graded write-up; update it when a
player-facing feature changes. [Story/](Story/README.md) holds the plot and a file per character (Oni, the bosses,
Kagetsune): read the character's file before writing their lines, scenes or art, and update it when they change.

## Layout

- Gameplay scripts: flat in `Assets/*.cs` (no subfolders, no namespaces, no asmdefs).
- Editor tooling: `Assets/Editor/*.cs` (menu commands under `Ninja/`).
- Art: `Assets/Art/` (`Sprites/` raw frames, `Characters/` CharacterArt assets, `Fx/`, `Portraits/`, `Fonts/`).
- Audio: `Assets/Audio/` (`Sfx/`, `Music/`, `Voice/`, `SfxLibrary.asset`).
- Node tooling outside Unity: `Tools/` (`npm run music`, `npm run sfx`, `npm run voice`; ElevenLabs key in gitignored `.env.local`).

## Working in the Unity Editor

- **Never change `.prefab` / `.unity` files on disk while Unity has them loaded** (git checkout/restore, hand
  edits, scripted rewrites). Unity 6000.6 segfaults on hot-reload. Make prefab/scene changes through Unity
  (editor scripts, UnityMCP tools); if a disk revert is needed, ask the user to close Unity first.
- Art, VFX, audio and boss wiring are generated by the `Ninja/Apply …` menu commands. Re-run the matching one
  after changing art/audio instead of wiring by hand. `Ninja/Apply Sprite Art` regenerates prefab child
  fileIDs, so ID-only diffs after it are expected.
- After script edits, check the Unity console for compile errors before using new types.
- Dev tools (Editor, development builds, and release builds while `GameManager.devToolsInRelease` is on): DEV TOOLS on the title/pause menu or **F3** jumps to any stage or
  boss; **F4** toggles god mode; **F1** kills the army, **F2** jumps to the last stage's boss, **F5** drops a soul (Fire → Frost → Storm), **F6** drops a technique scroll, **F9** charges the ultimate.
- Serialized defaults in code (e.g. `GameManager.stages`) are only initial values; the scene's saved values win.

## Code conventions

- Match the surrounding style: short plain-English comments explaining *why*, above the line they describe;
  no XML doc comments; implicit `private`; `[SerializeField]` private fields with `[Tooltip]` for tuning.
- Use `[FormerlySerializedAs]` when renaming a serialized field so scene/prefab values survive.
- Things the player can damage implement `IHittable`; damage per source lives in `Damage.Of`.
- Code-built objects (bosses, scouts, souls, UI) need no prefab; they fall back to placeholder visuals when
  art is missing. Keep that fallback behaviour when adding new content.
- Boon effect kills use `KillSource.Effect` and must never trigger further effects.
- Use `CameraShake.Center`, not the camera's live position, when measuring the view.
- Sounds go through `Sfx.Play(id)`, effects through `Fx.Play(id)`, with ids as constants on those classes.
